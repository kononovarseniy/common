# AGENTS.md

## Project

Header-heavy C++20/23 library (`ka::common`) of reusable types and functions.

## Project layout

- C++ files use `.hpp` extensions for headers and `.cpp` for source files.
- `include/ka/common/` — public `*.hpp` header files.
- `src/` — implementation files that do not require templates or `inline`, or need to be isolated from the header file. Each `src/foo.cpp` must have a corresponding `foo.hpp` either in `src/` or in `include/ka/common/`.
- `test/` — tests. Each header `foo.hpp` has a corresponding `test/foo_test.cpp`. Helper entities shared across multiple test files go into `test/helpers/` as `*.cpp` or `*.hpp`.

## Build

Uses **Conan 2** + **CMake**. After first clone or adding dependencies:

```sh
conan install . --build=missing -s build_type=Release
conan install . --build=missing -s build_type=Debug
```

Then build with CMake presets `conan-release` or `conan-debug` (defined in `CMakeUserPresets.json`, which is gitignored and generated by conan).

## Test

Tests use **Google Test** via the `ka_gtest_target` CMake macro and are discovered by CTest. Build and run all tests:

```sh
cmake --build build/<preset> && ctest --test-dir build/<preset> --output-on-failure
```

The tests include compile-failure tests that run as CMake build steps, not direct executables — they are expected to fail for certain configurations.
Windows runs these serially due to issues with parallel execution.

## Lint / Format

- **clang-format** (`.clang-format`): Microsoft-based style, Allman braces, 120-col limit, 4-space indent, `c++20` standard.
- **Line length**: 120 characters is a hard limit in code files (`.hpp`, `.cpp`, `.cmake`). In markdown files (`.md`) it is a recommendation, not a hard limit.
- Warnings are errors everywhere: `-Wall -Wextra -Wpedantic -Werror` (GCC/Clang), `/W4 /WX` (MSVC).

## Code conventions

- **Namespace**: `ka`, with `inline namespace` for file-local implementation code.
- **Include path**: `<ka/common/xxx.hpp>` convention.
- **Assertions**: for assertions, use macros `KA_ASSERT`, `KA_PRE`, `KA_POST`, `KA_UNREACHABLE` from `<ka/common/assert.hpp>`. Assertionas are disabled in `NDEBUG` builds. Assertions can be used both in `consteval` and runtime paths. The macros do not require extra parentheses around the condition when it contains commas.
- **Pragma wrappers**: for portable warning push/pop macros, use `<ka/common/pragma.hpp>`.
- **Arithmetic casts**: implicit conversions between arithmetic types are forbidden. For arithmetic casts, use functions from `<ka/common/cast.hpp>`.
  - `safe_cast` — when types always allow lossless conversion (guaranteed at compile time, no runtime asserts).
  - `exact_cast` — when the source type allows precision loss, but the caller guarantees it does not occur and expects the value to be preserved (includes runtime asserts for correctness).
  - `static_cast` — when value change during conversion is a normal part of the algorithm.
- **New headers**: must be added to `target_sources` in `CMakeLists.txt` under `PUBLIC FILE_SET HEADERS`.
- **New test files**: add to `ka_gtest_target` SOURCES list in `CMakeLists.txt`.
- **Compile-time tests**: when testing C++20 concepts and `constexpr`/`consteval` functions, use `static_assert` directly in the test file.
- **Comments**: use only single-line `//` comments ending with a period. Exception: multi-line macros may use `/* */` comments, because backslash line continuation must be the last character on the line.
- **Doxygen comments**: use `///` with `@` command syntax. Each entity must have a single-line `@brief` description, optionally followed by a multi-line `@details` description.
- **Markdown line breaks**: do not break a sentence across lines. Each sentence must fit on a single line. Line breaks are only allowed after a period (`.`), a colon (`:`) at the end of a heading or sentence, or a comma (`,`) separating semantic blocks in very long sentences. Multiple sentences in the same list item may each occupy a separate line.

## Language

Use **English** in all code, comments, commit messages, variable/function names, documentation, and responses. Do not use any other language.

## Dependencies

- Runtime: `fmt`
- Test: `gtest`
- C++20 is the hard minimum (`ka_require_cpp_standard(MIN 20 DEFAULT 23)`).
